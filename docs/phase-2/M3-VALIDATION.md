## Schema and migration evidence

`drizzle/0001_material_gladiator.sql` was generated by Drizzle Kit after `0000_rare_mantis.sql`; the M2 SQL was not edited. It adds four Better Auth-owned tables (`auth_users`, `auth_accounts`, `auth_sessions`, `auth_verifications`) and one domain-owned table (`application_accounts`) plus its two-value enum.

Agent-executed migration proof:

1. existing M2 database → `pnpm db:migrate` → success;
2. `pnpm db:seed` → all six fake accounts provisioned successfully;
3. guarded `pnpm db:reset:dev` → reset only `portal_dev`, applied M2 then M3, seeded domain rows and provisioned auth users → success;
4. post-reset M2 database suite → 12/12 passed;
5. post-reset authentication suite → 9/9 passed.

## Authentication test evidence

`pnpm test:auth` passed 9/9 integration tests against PostgreSQL:

1. all six `.invalid` users provision reproducibly through Better Auth;
2. valid credentials authenticate and set a session cookie;
3. invalid password and unknown email both fail with the same safe message;
4. the server retrieves the authenticated user/session and Person link;
5. anonymous protected access resolves null while an active session resolves identity;
6. logout ends the database session;
7. auth user joins explicitly to the expected Person;
8. the database rejects a second auth-user link to that Person (`23505`);
9. disabling an account revokes its sessions, denies the existing cookie, and blocks a new login.
