## Confirmed findings

### RC2A-F01 — P1: sign-out failure leaves misleading or unrecoverable UI

**Route/component:** `/account` and the shared sign-out control, also used by Account menus. **Owner:** `src/features/identity/sign-out-button.tsx`, `signOut()`.

Reproduction in an authenticated Student session at 375×812:

1. Open `/account`; intercept `/api/auth/sign-out` in that isolated browser session.
2. Abort the request. The page stays at `/account`; **Signing out…** remains disabled; no alert or retry appears. The browser reports `Failed to fetch`. Opening `/student` still renders authenticated content.
3. Repeat with HTTP 503. The UI redirects to `/login` with no error, but opening `/student` still renders authenticated content.
4. Remove interception and use normal sign-out. Protected access redirects to Login in both control cases.

The component sets pending and clears temporary presentation before awaiting sign-out, but does not handle rejection, inspect a returned error, or clear pending on failure. This is reproduced failure handling, not an authorization bypass. Normal session revocation passes.

**Expected:** only report completion/redirect after successful sign-out; on transport/server failure provide truthful accessible feedback, clear pending and enable retry. Preserve temporary presentation cleanup, session/cookie semantics and server guards. See [network-abort result](rc2a-audit/signout-network-abort-result-375.png) and [503 result](rc2a-audit/signout-http-503-result-375.png).

### RC2A-F02 — P2: legal links do not focus the destination heading

**Routes:** `/disclaimer`, `/terms`, `/privacy`, `/acceptable-use`, reached from disclosure. **Likely owners:** `src/features/disclosure/demo-disclosure-provider.tsx` (`information()`), `src/features/disclosure/project-information-page.tsx` and the smallest shared heading-focus integration required.

Before acknowledgement, open a legal link from disclosure. Navigation succeeds and the legal page is readable, but `document.activeElement` is `BODY`; the H1 is not programmatically focusable. The next Tab starts at **Skip to content**. All four legal destinations reproduce this; an independent fresh browser review confirms Privacy. The Next route announcer remains present, so this is a destination-orientation gap rather than an inaccessible legal page.

**Expected:** destination heading receives focus after link navigation, as required by FD7 lock §12; subsequent Tab proceeds through destination content in sensible order. Preserve legal exemptions, safe originating path/query, Return to demo, Back/Forward and acknowledgement semantics. Evidence: [Privacy focus](rc2a-audit/legal-focus-privacy-1440.png) and the four `legal-focus-*` images/targeted assertions.

### RC2A-F03 — P2: Technology account-directory warning repeats its title

**Route/component:** `/technology/accounts`, contextual `DemoNotice`. **Owner:** `src/app/[portal]/[[...section]]/page.tsx`, Technology branch.

Both `label` and `detail` receive **Read-only account directory**. The visible notice repeats the same sentence as heading and body. Confirmed source and rendered text are identical; [current image](rc2a-audit/technology-notice-duplicate-1440.png).

**Expected:** retain the task-specific read-only directory warning once, with useful non-repeating detail if needed. Preserve B36 meaning, directory content, role filtering and permissions. This is limited copy polish, not a generic notice redesign.

## Visual, motion, responsive and accessibility verdict

**Visual: PASS in reviewed evidence, with F03 copy polish.** The civic-academic visual identity remains coherent: Source Sans 3 UI, selective Source Serif 4 public typography, civic blue actions and restrained yellow anchors. Wide layouts preserve purposeful task/reading widths; mobile tables become useful lists. Reviewed states show no confirmed typography/weight, clipping, nested-panel/card-wall, dead-area, long-email/ID/BSCpE, footer or avatar defect. The latest corrected disclosure matches its source-hash manifest; it is readable at 320px, short landscape and doubled text. No redesign is proposed.

**Motion: PASS in sampled controls.** FD6 timings remain bounded: 140ms feedback, 80ms press, 180ms overlays/tabs, 220ms drawer and up to 320ms public connector treatment. State/content/focus are available without waiting for decoration. Keyboard sort, rows/selection, form feedback, tabs, popovers, dialogs, avatar interactions and public connectors were exercised. Reduced motion, including a preference change mid-disclosure, resolves decoration immediately; no tested overflow/layout-shift or delayed-content failure was found.

**Responsive: PASS in the executed Chromium matrix.** The fresh FD6 run measured 15 routes at each of 320×812, 375×812, 768×900, 1440×900 and 1920×1080: 75 measurements, no page overflow. The M7 run adds 55 passing measurements, including representative text enlargement. The disclosure/legal runner independently covers all five widths, 812×375 landscape, doubled text and storage/error states. Doubled-text samples include Account, Applicant application/Profile, Records and disclosure; they are a text-sizing simulation, not proof of real browser zoom or every UI-state combination.

**Accessibility: PASS in sampled checks except F02.** Keyboard skip link, focus-visible, sort/`aria-sort`, labeled inputs/errors, tab selection, dialog/drawer containment, Escape and return focus passed their exercised paths. Sample measured contrasts: ink/canvas 13.71:1, blue/white 10.54:1, ink/yellow 11.71:1, input text 15.67:1 and avatar-plus boundary 7.88:1. The audit does not claim every color pair or touch target was measured. There is no WCAG certification claim.

The source/evidence assessment confirms A01–A15 global clauses remain consolidated and B01–B42 task-specific warnings remain, including the eight contextual `DemoNotice` sites and four supplemental notice sentinels. Privacy describes real login/session cookies and the version-only disclosure preference, while photo/bio and sample-workflow behavior remains honestly temporary. No unsupported official-school, delivery, upload, monitoring or certification claim was found in the inspected content. ## P3 limitations and release gates

These are documented scope limits or pending checks, not invented defects:

- Edge Chromium only; no physical-device, Safari/WebKit, Firefox or actual screen-reader listening acceptance. Real zoom/software-keyboard and printed/PDF pagination need targeted external/device verification where available.
- Browser-only sample workflows and temporary photo/bio are intentional. No real records, admissions decision, upload, dispatch, recovery email, live monitoring or institution production service is established.
- Zero-membership behavior is source-supported but not a seeded live identity; no extra identity was created to test it. Not every search/filter/scenario/entity Cartesian combination was executed.
- Local sign-in and route tests do not certify a public host. Before credentials are exposed, verify approved shared-password acceptance for all nine, the exact demo-only allowlist, no non-demo use, correct permissions and fictional-only data on the actual release database.
- Better Auth's library route family exposes more than the custom sign-in UI. Shared-account mutation, effective abuse controls and concurrent-reviewer stability must be checked before exposure. No password/name/delete action was attempted against the nine shared identities in this read-only phase; this is a release gate, not a claimed exploit.
- The source reviewer found zero configured-secret literal hits in 243 tracked text files and no sampled private-key/common cloud-token pattern; only `.env.example` is tracked. Git history, client build output and deployed logs/configuration were not certified. Verify those, HTTPS/origin/cookie settings and privacy accuracy on the actual public host.
- RC2B must run the full final implementation gates. No new unit/integration/lint/type/build results are claimed here. Historical repository-wide formatting debt remains in the four files recorded by FD3/FD4/FD8; do not silently reformat unrelated evidence.

Public release stays blocked until F01 is fixed, the two accepted P2 fixes are verified, the account-release checks pass, and the owner explicitly authorizes credential exposure/publication.
